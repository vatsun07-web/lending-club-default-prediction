# LendingClub Loan Default Prediction

An end-to-end machine learning pipeline for predicting loan defaults on 2.26M LendingClub loans, built following the **CRISP-DM methodology** across 9 structured stages.

---

## Results

| Metric | Baseline (no weighting) | Final Model |
|---|---|---|
| ROC-AUC | 0.70 | **0.7117** |
| Recall (Default class) | 0.03 | **0.8741** |
| Precision | — | 0.2262 |
| PR-AUC | — | 0.3345 |
| Decision Threshold | 0.50 | **0.3592** (optimised) |

> Recall improved from **3% → 87%** through class weighting and threshold optimisation — without any change to model architecture.

**Estimated business value: +$628M** on a 264,370-loan test set, assuming LGD = 80% and loan margin = 8%.

---

## Key Finding

> *The gap between a 0.71 ROC-AUC and the 0.80 target is not a failure of technique — it is a discovery about the limits of information available at loan origination. The dominant predictor, `int_rate`, is LendingClub's own risk pricing signal. The model largely re-ranks what the lender already knows. Closing the remaining gap requires better data, not better algorithms.*

## Imbalanced Learning Protocol

Class imbalance (17.22% default rate, 4.8:1 ratio) was addressed in three deliberate steps:

1. **Baseline** — no resampling, default threshold 0.50 → Recall 3%
2. **Class weighting** — `scale_pos_weight=4.8` → Recall 66%
3. **Threshold optimisation** — PR curve optimised cutoff 0.3592 → Recall 87%

ROC-AUC was unchanged across all three steps, confirming the information ceiling is a data constraint, not a modeling one.

## Reproducing the Pipeline

### 1. Get the data
Download the LendingClub loan dataset from [Kaggle](https://www.kaggle.com/datasets/wordsforthewise/lending-club) and place it as `lending_club.db` in the project root.

### 2. Install dependencies
```bash
pip install -r requirements.txt
```

### 3. Run notebooks in order
```bash
jupyter notebook
```
Run notebooks `00` through `08` in sequence. Each stage saves its output to `data/` or `models/` for the next stage to load.

> **Hardware note:** Built on MacBook Air M1 (8GB RAM). Memory-efficient patterns used throughout — SQLite aggregation, category dtypes, early column dropping, chunked parquet writes.

## Limitations

- **Calibration:** XGBoost with class weighting produces shifted probability estimates. Scores are relative risk rankings only — not empirical probabilities. Platt scaling required before use in risk pricing.
- **Vintage scope:** Training covers 2007–2016 only. Post-2016 performance (COVID, 2022–2023 rate environment) is unknown.
- **Grade A Recall = 15.2%:** Grade A defaults are caused by post-origination shocks (job loss, medical events) that no application-time model can predict.
